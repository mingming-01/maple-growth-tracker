# 캐릭터 정보 새로고침과 데이터 최신성

## React 기본 화면 (`/`)

- React 화면은 같은 브라우저 탭의 `sessionStorage`에서 검색 결과와 화면 상태를 복원합니다.
- 페이지를 다시 열거나 새로고침했다고 해서 복원된 결과를 자동으로 Nexon API에 재조회하지는 않습니다.
- 화면의 **최신 정보 다시 조회** 버튼을 누르면 캐릭터 정보와 최근 성장 기록을 `refresh=1`로 요청합니다. 프런트엔드는 해당 요청에 브라우저 캐시를 사용하지 않고, 서버도 캐릭터·성장 기록의 일반 응답 캐시를 건너뜁니다.
- 이 동작은 Nexon Open API에 새 조회를 요청하는 것이며, 게임 클라이언트나 넥슨 서버의 캐릭터 데이터 갱신을 직접 실행하는 기능은 아닙니다.

## 기존 Vanilla JS 화면 (`/legacy/`)

- 기존 화면도 같은 탭의 `sessionStorage`에서 마지막 검색 결과를 복원합니다.
- 저장된 캐릭터가 있고 마지막 자동 갱신 시각으로부터 60초 이상 지났다면 페이지 초기화 과정에서 자동 갱신을 시도합니다.
- 마지막 자동 갱신 이후 60초가 지나지 않았다면 자동 요청은 생략하고, 사용자가 직접 **최신 정보 다시 조회** 버튼을 누를 수 있도록 안내합니다.
- 수동 갱신은 이 60초 자동 갱신 간격과 별개로 실행됩니다.

## 공통 동작과 한계

- 캐릭터 정보와 최근 성장 기록의 강제 갱신은 서버 메모리 캐시를 건너뛰고 Nexon Open API를 다시 요청합니다. 상세 정보 탭은 별도 요청이며, 사용자가 상세 탭에서 새로고침을 요청했을 때 해당 영역의 캐시를 건너뜁니다.
- 서버가 Nexon API의 일시적인 오류를 감지하고 마지막 정상 스냅샷을 보유하고 있으면, 이전 데이터를 반환하고 `dataStatus`를 `stale`로 표시할 수 있습니다. 스냅샷이 없으면 오류 응답을 반환합니다.
- 앱의 조회 시각은 웹앱이 API를 조회한 시각입니다. 게임 내 변경 사항이 Nexon Open API에 반영된 시각을 의미하지 않습니다.
- 웹앱은 게임 클라이언트의 캐시샵 입장, 캐릭터 선택, 재접속 등의 동작을 대신 수행하지 않습니다. 넥슨 측 집계·캐시 갱신 지연이 있으면 새 조회를 실행해도 이전 데이터가 반환될 수 있습니다.
- 랭킹 데이터의 제공 시점과 과거 조회 가능 범위는 Nexon Open API 정책에 따릅니다. 과거 날짜의 정보가 제공되지 않으면 임의로 경험치나 랭킹을 계산해 채우지 않습니다.

## 데이터 저장과 캐시의 구분

- 화면 상태는 브라우저 `sessionStorage`에 저장되므로 같은 탭에서 복원되며, 서버 DB의 성장 기록과는 별개입니다.
- 관심 캐릭터와 성장 목표, AI 리포트 캐시는 브라우저 `localStorage`에 저장됩니다.
- 장기 성장 기록은 `GROWTH_DATABASE_URL`이 PostgreSQL을 가리키면 PostgreSQL에 저장하고, 설정이 없는 로컬 개발 환경에서는 SQLite를 사용합니다.
- API 응답 스냅샷과 관리자 로그도 같은 DB 연결 설정을 사용합니다. 일부 저장소는 PostgreSQL 연결에 실패하면 SQLite로 전환하고 관리자 화면 또는 저장 상태에 경고를 표시할 수 있으므로, 운영 환경에서는 화면에 표시되는 저장소 상태를 확인해야 합니다.
- 서버 메모리 캐시와 성능 계측값은 서버 프로세스 단위입니다. 프로세스 재시작 시 초기화되며, DB에 저장하는 장기 성장 기록과 동일한 보존 데이터가 아닙니다.
