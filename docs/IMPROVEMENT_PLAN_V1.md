# Maple Growth Tracker 개선 계획 v1

## 프로젝트 방향

기존 캐릭터 성장 분석 기능을 유지하면서, 외부 API 장애 대응, 장기 성장 기록 보존, AI 분석의 안정성을 차례로 개선한다.

## 1단계 — 현재 구조 점검 및 조회 안정화

- 캐릭터 조회와 최근 7일 기록의 요청 흐름을 확인한다.
- 외부 API 요청 시간 제한과 오류 처리를 보완한다.
- 당일 데이터가 준비되지 않은 경우와 실제 API 장애를 구분한다.
- 이전 정상 데이터를 보여줄 때 기준일과 데이터 상태를 표시한다.

## 2단계 — 성장 기록 보존

- 정상 조회 결과를 날짜별로 저장한다.
- 서버 재시작 후에도 기록이 유지되는 저장 구조를 마련한다.
- 누락된 날짜와 조회 실패를 정상 데이터와 구분한다.
- 30일·90일 성장 추이를 계산할 수 있도록 데이터 구조를 설계한다.

## 3단계 — AI 분석 복원력 개선

- Gemini와 OpenRouter 호출의 시간 제한 및 오류 분류를 보완한다.
- 동일한 데이터에 대한 불필요한 AI 재호출을 줄인다.
- 두 AI 서비스가 모두 실패하면 코드 기반 기본 성장 분석을 제공한다.
- AI 분석 실패가 캐릭터 정보와 그래프 표시까지 막지 않는지 확인한다.

## 4단계 — 장기 성장 기능 개선

- [x] 30일·90일 저장 기록을 성장 그래프에 반영한다.
- [x] 직전 동일 기간의 관측 일 평균을 비교하고 기록 충실도·최고 성장일·성장 활동일·레벨업을 요약한다.
- [x] 현재 조회한 캐릭터를 최대 30명까지 브라우저 관심 목록에 저장하고, 다시 조회하거나 제거한다.
- [x] AI 리포트에 분석 대상 기간, 정상 확인 기록 수, 변화량 확인 구간 수, 최근 정상 기록일을 표시한다.
- [x] 기록이 누락되거나 API가 제공하지 않은 날짜를 임의로 보정하지 않았음을 사용자에게 알린다.

### Phase 4 검증 기준

- 30일·90일 선택 시 해당 기간의 기록이 그래프와 타임라인에 반영되어야 한다.
- 직전 동일 기간 기록과 비교할 수 있어야 하며, 관측 자료가 부족하면 추정하지 않는다.
- 관심 캐릭터 등록·재조회·삭제가 브라우저 저장소 기준으로 동작해야 한다.
- AI 분석 근거는 실제 history 응답에서 계산되어야 하고 캐시·새로고침 복원에서도 일치해야 한다.
- 자동화 테스트에서 기간 그래프, 관심 목록, AI 근거 표시를 검증한다.

## 5단계 — AI 성장 분석 고도화

- [x] 최근 7일과 직전 7일의 관측 평균 성장량 비교
- [x] 주중·주말 관측 성장량 분포
- [x] 분석 기준일과 데이터 충실도 산출
- [x] 누락 날짜·레벨업·비정상 감소 구간의 무리한 연결 방지
- [x] AI에 계산된 인사이트만 전달하고 근거를 화면에 표시

세부 기준: [Phase 5 AI 성장 분석 문서](PHASE5_AI_GROWTH_INSIGHTS.md)

## 8단계 — 배포 및 최종 검증

- 현재 Render 배포 환경의 데이터 보존과 재기동 동작을 확인한다.
- 영구 데이터 저장소와 배포 플랫폼의 조합을 비교한다.
- Vercel 시험 배포 또는 Render 유지 방안을 결정하고 주요 기능을 재검증한다.

## 진행 원칙

- 기존 기능과 동작을 유지하는 것을 우선한다.
- 실제 코드와 데이터 흐름을 확인한 다음 수정한다.
- 가능한 테스트를 실행하고 결과를 확인한다.
- 검증되지 않은 항목은 완료로 표시하지 않는다.
- 단계별 변경 내역과 검증 결과를 기록한다.
