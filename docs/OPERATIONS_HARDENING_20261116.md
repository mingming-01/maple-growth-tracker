# 운영 안정성 개선 통합 작업 (2026-11-16)

- 기준 브랜치: `main`
- 기준 커밋: `77787662b294d12fb5b736879596f6f5fa388093`

- Render 인스턴스: Free, 1개
- 실행 명령: `gunicorn app:app`

- Supabase: PostgreSQL 17.11, `ACTIVE_HEALTHY`

## 1. 운영 환경 점검

### 확인된 사항
- Render 서비스가 `main` 브랜치를 추적하고 커밋 기반 자동 배포를 사용한다.
- 현재 서비스 인스턴스 수는 1개다.
- 배포 로그에서 `WEB_CONCURRENCY=1`이 설정되고 Gunicorn sync worker 1개가 시작되는 것을 확인했다.
- Supabase 프로젝트는 정상 상태다.
- 앱 시작 로그에서 `FLASK_SECRET_KEY` 미설정 경고와 `TRUSTED_PROXY_HOPS=0` 경고가 확인됐다.

### 확인 한계
- 연결된 Render 도구는 환경변수 값을 조회하는 기능을 제공하지 않는다. 비밀값을 노출하거나 변경하지 않았으며, 시작 로그와 코드에서 확인 가능한 상태만 기록했다.
- `TRUSTED_PROXY_HOPS`는 프록시 체인을 확인하지 않은 상태에서 임의로 설정하지 않는다.

## 2. 멀티워커 제한 개선

- 기존 공개 API IP별 제한은 `api_request_limit_state`를 통해 PostgreSQL 행 잠금으로 공유한다.
- AI 요청 제한은 분당·IP별 일일·전체 일일 사용량을 `shared_rate_limit_state`의 트랜잭션으로 공유하도록 확장한다.
- Nexon 호출 간격은 전역 예약 행을 잠가 워커 간 호출 시각을 직렬화한다.
- PostgreSQL 저장소를 사용할 수 없으면 기존 프로세스 메모리 제한기로 폴백한다. 이 경우 워커 간 제한이 일시적으로 분리될 수 있으므로 로그에 경고한다.

### DB 변경 통제
- 운영 DB를 직접 수정하지 않았다.
- 새 테이블은 `migrations/20261116_shared_rate_limit_state.sql`로 분리했다.
- 운영 적용 전에는 이 마이그레이션을 명시적으로 적용해야 한다. 적용 전 코드가 테이블을 찾지 못하면 기존 메모리 제한기로 폴백한다.

## 3. AI 입력 검증 및 서버 계산

- AI 분석에서 클라이언트가 전달한 성장 지표·기간 요약·날짜별 기록을 근거 데이터로 사용하지 않는다.
- 캐릭터 기본 정보는 Nexon API에서 확인하고, 성장 기록은 서버 저장소에서 조회한다.
- 경험치 증가량, 연속 날짜, 레벨업 전환, 랭킹 변화, 기간 요약을 서버에서 재계산한다.
- 비교 분석도 캐릭터명을 다시 확인하고 각 캐릭터의 저장 기록을 서버에서 조회해 지표를 재계산한다.
- 저장된 기록이 부족하거나 조회할 수 없으면 임의로 보완하지 않고 자료 부족 또는 저장소 오류를 반환한다.

## 4. PostgreSQL 통합 테스트

- GitHub Actions에 격리된 PostgreSQL 16 서비스 컨테이너를 추가한다.
- 테스트 전용 DB에 마이그레이션을 적용한 뒤 저장·복원, AI 제한 동시성, Nexon 호출 슬롯 예약을 검증한다.
- 운영 Supabase DB를 테스트 대상으로 사용하지 않는다.
- 로컬에서 `TEST_POSTGRES_URL`이 없으면 PostgreSQL 통합 테스트는 건너뛰고, CI에서는 컨테이너를 통해 실행한다.

## 5. 레거시 정리 판정

- 현재 `/` React 화면 외에 `/legacy/`, `/preview/`, React 빌드 실패 시 루트 폴백이 남아 있다.
- 기존 운영 점검 문서에 따라 Render 운영 URL의 React 주요 기능 및 관리자 화면을 실환경에서 확인하기 전에는 레거시 라우트·템플릿·JS/CSS를 삭제하지 않는다.
- 이번 작업에서는 무리한 삭제 대신 기존 실행 경로를 유지하고 전체 회귀 테스트를 CI에 맡긴다.
- 따라서 5단계 중 코드 의존성 재검토는 수행하지만, 레거시 퇴역은 운영 화면 검증이 끝날 때까지 보류한다.
